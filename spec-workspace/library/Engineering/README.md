# Engineering

Cross-cutting engineering practices, standards, and constraints that apply across every project.

These artifacts are deliberately narrow: they state *how work must be done*, never *what a product
must do*. Product behaviour belongs in a project's specification collection under
`spec-workspace/projects/<project-name>/`.

## Status

**Empty by design.** No engineering practice has been authored yet. The process-level constraints
that currently exist are the protected invariants in
`sdlc-framework/policies/protected_policy_reference.md` - those govern the *framework*, not
product engineering, and are referenced from there rather than duplicated here.
